Поговорим о **стандартных функциях** _Kotlin_, которые используются чаще всего в разработке. Стандартные, потому что входят в **Kotlin standard library**. Давайте разбираться, для чего они нужны.

В этом юните у нас будет использоваться понятие **receiver**, потому как под капотом стандартные функции — это **extension functions**, и **receiver** является субъектом _extension_ функции, напомню:

fun String.addDashes() = "-$this-"

Строка, на которой мы применим наш _extension_,__ будет **receiver**__.__

## **apply**

Эта функция может рассмотрена как функция для настройки конфигурации объекта. Например, вот здесь мы не используем `apply`:

val list = mutableListOf(1, 3, 2, 4) //Создаем лист

list.add(0)//добавляем новый элемент в конец
list.removeAt(4)//убираем элемент с индексом 6
list.sort()//сортируем
list.clear()//очищаем лист

А вот здесь используем:

val list = mutableListOf(1, 3, 2, 4).apply { //Создаем лист
   add(0) //добавляем новый элемент
   removeAt(0) //убираем элемент с индексом 0
   sort() //сортируем
   clear() //очищаем лист
}

Код получается более читабельный и лаконичный. Как видите, мы перечисляем всё, что хотим сделать с объектом, в фигурных скобках, не указывая явно наш объект.

## **let**

В отличие от `**apply**`, который не передает **receiver** в лямбду, функция `**let**` его передаёт знакомым вам уже ключевым словом `**it**`, с которым вы можете сделать необходимые действия и вернуть его. Посмотрим на примере:

val list = mutableListOf(1, 3, 2, 4).first().let { //Берем первый элемент
   it + it * 100
}

println(list) // Вывод в консоль 101

Также `**let**` можно совместить с другими синтаксическими конструкциями, пример с Элвисом для обработки `**null**`, смотрим пример:

fun sayHey(name: String?): String {
   return name?.let {
       "Hey, $it"
   } ?: "Hey, stranger"
}

В этом примере мы допускаем, что вместо строки нам может прийти `**null**`, и при помощи `**let**` и Элвиса мы это изящно обрабатываем. Конструкция с `**if else**` выглядела бы куда менее привлекательно, сравните сами:

fun sayHey(name: String?): String {
   return if (name != null) {
       "Hey, $name"
   } else {
       "Hey, stranger"
   }
}

Ещё раз обозначим различия между `**let**` и `**apply**`:

- `**let**` передает _receiver_ в лямбду, а `**apply**` — нет;
- `**apply**` передает текущий _receiver_, `**let**` передает как результат последнюю строку в лямбде;
- `**let**` не меняет _receiver_, а лишь его применяет, поэтому в отличие от `**apply**`, изменения _receiver_ внутри лямбды не поменяет сам _receiver_.

## **run**

`**Run**` похож по действию на `**apply**`, только в отличие от `**apply**`, `**run**` не возвращает _receiver_, он возвращает результат лямбды, то есть то, что было указано в последней строке.

Пример:

val list = mutableListOf(1, 3, 2, 4).run {
   size == 4
}

println(list) // Вывод в консоль true

## **with**

Это, по сути, вариация `**run**`, ведёт она себя точно таким же образом, но имеет другой синтаксис:

val list = with(mutableListOf(1, 3, 2, 4)) {
   size == 4
}

То есть мы передаем наш _receiver_ как аргумент вместо вызова функции сразу на нём, как было в примере выше.

В виду худшей читабельности, лучше отдавать свое предпочтение `**run**`. Этот вариант приведён здесь, на случай, если вы где-то с таким написанием столкнетесь.

## **also**

Эта функция ведёт себя подобно `**let**`, но, как вы помните, `**let**` возвращает результат лямбды, а `**also**` будет возвращать **receiver**.

`**Also**` будет удобен, когда мы хотим как-то изменить наш _receiver,_ или как-то его использовать (например напечатать) последовательно несколько раз, давайте посмотрим:

mutableListOf(1, 3, 2, 4)
       .also {
           it.sort() // сортируем
       } .also {
           println(it) // Вывод в консоль: [1, 2, 3, 4]
       }

Как видим, мы сначала отсортировали, а потом вывели на печать.

## **takeIf**

И так последняя в нашем списке, но не по значимости, функция `**takeIf**`. Она несколько отличается от тех, что уже были. Она проверяет условие, которое было передано в лямбду (ещё это называют `**Predicate**`) и, если условие выполняется, то она передает наш _receiver_, если нет — возвращает `**null**`.

Давайте посмотрим в коде:

val list = mutableListOf(1, 3, 2, 4).takeIf {
   it.size == 4 // Проверяем длинну листа
}?.get(3) // И если длинна 4, то берем 3 элемент

То есть `**takeIf**` будет полезен, когда мы хотим проверить какое-то условие, перед тем как что-либо выполнить. Этот же функционал можно реализовать и через `**if else**`:

val list = mutableListOf(1, 3, 2, 4)

val element = if (list.size == 4) {//Создаем временную переменную
   list[3]
} else {
   null
}

Как и в большинстве случаев до этого, получилось громоздко и менее читабельно. Главное, что стоит понять про `**takeIf**`: он нужен для того, чтобы получить `null` и потом его как-то обработать, в первую очередь, он пригодится для проверки условия перед выполнением другого кода. По сути это `**if else**`, который мы можем вызвать напрямую на объекте, не прибегая к использованию временных переменных.

**Совет от эксперта.** Ещё есть `**takeUnless**`, как вы поняли, он работает противоположным образом. То есть он вернет нам receiver, если условие в лямбде не выполнилось, и `null`, если выполнилось. Рекомендуется его не использовать, так как он может вызвать путаницу.

| ------------ | ---------------------------------- | ------------------------- | ---------------- |

| `**let**`    | Да                                 | Нет                       | Результат лямбды |
| `**run**`    | Нет                                | Да                        | Результат лямбды |
| `**with**`   | Нет                                | Да                        | Результат лямбды |
| `**also**`   | Да                                 | Нет                       | receiver         |
| `**takeIf**` | Да                                 | Нет                       | receiver/null    |
