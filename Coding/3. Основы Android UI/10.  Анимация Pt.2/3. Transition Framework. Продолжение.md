# Класс Transition и встроенные эффекты

**Transition** — это класс, описывающий логику и характер перехода между двумя сценами. Он представляет собой набор анимаций, выполняющихся параллельно или последовательно для всех объектов сцены (или только для явно указанных целей — `target`).

---

## 🛠 Основные методы класса Transition

| Метод | Описание работы |
| :--- | :--- |
| `getDuration(): Long` | Возвращает текущую длительность перехода. |
| `setDuration(duration: Long): Transition` | Устанавливает длительность перехода в миллисекундах. |
| `setInterpolator(interpolator: TimeInterpolator)` | Задает интерполятор (функцию изменения скорости анимации во времени). |
| `addTarget(targetId: Int): Transition` | Добавляет `View` (по ID или ссылке) в качестве **цели**. Анимация применится *только* к этим элементам. |
| `removeTarget(targetId: Int): Transition` | Исключает `View` из списка целей данного перехода. |
| `addListener(listener: TransitionListener)` | Добавляет слушатель для отслеживания жизненного цикла анимации (старт, конец и др.). |
| `setEpicenterCallback(callback: EpicenterCallback)` | Задает **эпицентр** перехода — область (`Rect`), от которой волной начинается анимация (например, центр экрана в `Explode`). |
| `setPropagation(propagation: TransitionPropagation)` | Устанавливает логику задержек (`Propagation`) для упорядоченного запуска анимаций элементов. |

---

## 📦 Встроенные реализации Transition

Google предоставляет несколько готовых классов переходов:

1. **`ChangeBounds`** — отслеживает и анимирует изменение координат (`layout position`) и размеров `View`.
2. **`Fade`** — классическое растворение/проявление. Наследуется от `Visibility`. Анимирует появление элементов (`Fade.IN`) или их исчезновение (`Fade.OUT`).
3. **`TransitionSet`** — контейнер для объединения нескольких переходов в группу (аналог `AnimationSet`).
4. **`AutoTransition`** — дефолтный переход, который запускается, если не указан другой. 
   > [!info] Схема работы AutoTransition:
   > Сначала исчезают отсутствующие элементы (`Fade.OUT`) ➡️ затем перемещаются и меняют размер оставшиеся (`ChangeBounds`) ➡️ в конце проявляются новые элементы (`Fade.IN`).
5. **`Explode`** — эффект «взрыва». Элементы разлетаются в разные стороны от эпицентра (центра экрана или области клика).
6. **`Slide`** — эффект «выдвижения». Позволяет элементам плавно въезжать на экран или выезжать с него (сверху, снизу, слева или справа).

## 🔗 Работа с TransitionSet

`TransitionSet` позволяет группировать переходы. Порядок их выполнения настраивается свойством **ordering** (`transitionOrdering` в XML).

### Вариант 1: Объявление в XML
Файлы создаются в папке `res/transition/`.

📁 **res/transition/transition_set.xml**
```xml
<?xml version="1.0" encoding="utf-8"?>
<transitionSet xmlns:android="[http://schemas.android.com/apk/res/android](http://schemas.android.com/apk/res/android)"
   android:transitionOrdering="sequential"> <!-- Выполнение друг за другом -->
   
   <slide android:slideEdge="start" android:duration="600"/>
   <changeBounds/>
   <fade android:fadingMode="fade_in" android:duration="800"/>
</transitionSet>
```

- `sequential` — переходы выполняются строго по очереди.
    
- `together` — все вложенные переходы стартуют одновременно.
    

### Вариант 2: Программное создание (Kotlin)

📁 **scene1.xml**

XML

```
<?xml version="1.0" encoding="utf-8"?>
<androidx.constraintlayout.widget.ConstraintLayout 
   xmlns:android="[http://schemas.android.com/apk/res/android](http://schemas.android.com/apk/res/android)"
   xmlns:app="[http://schemas.android.com/apk/res-auto](http://schemas.android.com/apk/res-auto)"
   android:layout_width="match_parent"
   android:layout_height="match_parent">

   <FrameLayout android:background="#7C4DFF" android:id="@+id/rect" android:layout_height="120dp" android:layout_width="120dp" app:layout_constraintEnd_toEndOf="parent" app:layout_constraintStart_toStartOf="parent" app:layout_constraintTop_toTopOf="parent"/>
</androidx.constraintlayout.widget.ConstraintLayout>
```

📁 **MainActivity.kt**

Kotlin

```
class MainActivity : AppCompatActivity() {
   override fun onCreate(savedInstanceState: Bundle?) {
       super.onCreate(savedInstanceState)
       setContentView(R.layout.activity_main)

       // 1. Создаем TransitionSet программно
       val setIn = TransitionSet().apply {
           addTransition(Fade())
           addTransition(Slide().apply {
               slideEdge = Gravity.BOTTOM
               duration = 1500
           })
           // Устанавливаем ОДНОВРЕМЕННОЕ выполнение
           ordering = TransitionSet.ORDERING_TOGETHER 
           // Для последовательного: TransitionSet.ORDERING_SEQUENTIAL
       }

       val scene1 = Scene.getSceneForLayout(root, R.layout.scene1, this)
       
       // Применяем быстрый переход с кастомным TransitionSet по клику
       root.setOnClickListener {
           TransitionManager.go(scene1, setIn)
       }
   }
}
```


## 🌊 Управление задержками: Propagation

Когда элементов на экране много (например, элементы списка или сетки), одновременный старт анимации создает визуальный хаос. Для упорядочивания используется **`TransitionPropagation`**.

`Propagation` рассчитывает индивидуальную задержку старта (`startDelay`) для каждого отдельного `View` в зависимости от его положения на экране.

### Встроенные типы Propagation:

- **`SidePropagation`** — анимация распространяется линейно от одного края экрана к другому. Идеально подходит для вертикальных и горизонтальных списков (`RecyclerView`).
    
- **`CirclePropagation`** — анимация расходится круговой волной из определенной точки (эпицентра). Идеально подходит для таблиц, плиток и сеток элементов (`GridLayout`).
