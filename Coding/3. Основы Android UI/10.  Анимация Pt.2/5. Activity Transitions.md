# Анимация переходов между Activity

`Transitions Framework` поддерживает встроенные анимации переходов не только между внутренними сценами, но и между полноценными экранами (`Activity`). 

Все переходы делятся на 3 основных сценария.

---

## 🔀 Сценарий 1 и 2: Прямой и обратный переходы

При перемещении пользователя между экранами $A$ и $B$ фреймворк оперирует четырьмя типами анимаций.

### ➡️ Прямой переход (Из Activity A в Activity B)
Когда пользователь открывает новый экран:
*   **`ExitTransition`** — запускается на стороне **Activity A** (экран, который мы покидаем и перестаем видеть).
*   **`EnterTransition`** — запускается на стороне **Activity B** (новый экран, который появляется перед пользователем).

### ⬅️ Обратный переход (Из Activity B в Activity A)
Когда пользователь возвращается назад (например, нажимает кнопку `onBackPressed`):
*   **`ReturnTransition`** — запускается на стороне **Activity B** (экран, который закрывается). По умолчанию зеркально повторяет свой `EnterTransition`.
*   **`ReenterTransition`** — запускается на стороне **Activity A** (экран, на который мы возвращаемся). По умолчанию зеркально повторяет свой `ExitTransition`.

---

## 🪄 Сценарий 3: Переходы с общим элементом (Shared Elements)

**Shared Element Transition** — это плавная анимация перемещения одного или нескольких графических элементов, которые присутствуют одновременно на исходном и конечном экранах (например, аватар пользователя плавно «перелетает» из элемента списка в шапку детального экрана).

> [!important] Связующий элемент `transitionName`
> Чтобы система поняла, какие именно `View` на Экране A и Экране B являются одним и тем же объектом, им обоим в XML-разметке должен быть присвоен **абсолютно одинаковый** атрибут `android:transitionName="уникальное_имя"`.

---

## 💻 Программная реализация перехода

Для запуска анимированного перехода используется класс `ActivityOptions` и его метод `makeSceneTransitionAnimation`. Он собирает информацию о переходе и упаковывает её в `Bundle`, который передается в метод `startActivity`.

### 📑 Сигнатура ключевого метода:
```kotlin
fun makeSceneTransitionAnimation(
    activity: Activity, 
    vararg sharedElements: Pair<View, String>
): ActivityOptions
```

- `activity` — ссылка на текущую Activity (`this`).
    
- `sharedElements` — необязательный список аргументов (передается через запятую). Каждая пара связывает конкретный `View` на текущем экране с его строковым `transitionName`.
    

### 🚀 Вариант 1: Обычный переход (Без Shared-элементов)

Kotlin

```
// 1. Создаем опции для анимации перехода
val options = ActivityOptions.makeSceneTransitionAnimation(this)

// 2. Создаем стандартный Intent
val intent = Intent(this, SecondActivity::class.java)

// 3. Запускаем, передавая опции, сконвертированные в Bundle
startActivity(intent, options.toBundle())
```

### 🚀 Вариант 2: Переход с общими элементами (Shared Elements)

Предположим, у нас есть `imageView` и `titleTextView` на Экране А, которые должны плавно перетечь на Экран Б.

Kotlin

```
val intent = Intent(this, SecondActivity::class.java)

// Создаем опции и передаем пары (Компонент -> Его transitionName)
val options = ActivityOptions.makeSceneTransitionAnimation(
    this,
    Pair(imageView, "avatar_transition"),
    Pair(titleTextView, "title_transition")
)

startActivity(intent, options.toBundle())
```
