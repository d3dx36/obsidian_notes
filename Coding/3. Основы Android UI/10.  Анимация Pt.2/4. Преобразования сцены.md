# Динамические переходы и отслеживание событий

Если нужно анимировать изменение лишь небольшой части экрана (например, размеры одной кнопки или смену картинки), создавать полноценные отдельные `Scene` (Сцены) через XML накладно. Для таких задач используется динамическое формирование сцен прямо в коде.

---

## ⚡ Формирование сцены с помощью beginDelayedTransition

Метод `beginDelayedTransition` — это статический метод класса `TransitionManager`, который позволяет автоматически анимировать любые изменения UI без создания объектов `Scene`.

```kotlin
TransitionManager.beginDelayedTransition(sceneRoot: ViewGroup, transition: Transition)
```

### Как это работает:

1. Вы вызываете `beginDelayedTransition`.
    
2. Система **фиксирует (запоминает)** текущее состояние, размеры и координаты всех `View` внутри указанного `sceneRoot`.
    
3. На следующем кадре (`frame`) система сравнивает новые изменившиеся свойства элементов со старыми.
    
4. На основе разницы автоматически запускается переданный `Transition`. Если анимация не передана вторым аргументом, сработает дефолтный `AutoTransition`.
    

### 💻 Пример использования:

Kotlin

```
// Указываем корень и тип анимации (Slide)
TransitionManager.beginDelayedTransition(root, Slide())

// Изменяем состояние элементов — фреймворк сам запустит анимацию сдвига
root.children.forEach { it.translationX += 10 }
```

## 🎧 Отслеживание событий: TransitionListener

Интерфейс `Transition.TransitionListener` позволяет перехватывать и обрабатывать жизненный цикл анимации перехода.

### Сводная таблица событий (Callback-методы)

|**Событие**|**Описание работы**|
|---|---|
|`onTransitionStart`|Срабатывает в момент **запуска** перехода.|
|`onTransitionEnd`|Срабатывает, когда переход успешно **завершился**.|
|`onTransitionCancel`|Вызывается, если переход был **отменен** в процессе выполнения.|
|`onTransitionPause`|Вызывается, если переход поставили **на паузу**.|
|`onTransitionResume`|Срабатывает при **возобновлении** анимации после паузы.|

> [!tip] Архитектурная деталь
> 
> Каждый callback-метод принимает аргумент `transition: Transition?`. Это сделано для того, чтобы один и тот же слушатель можно было вешать на группы переходов (`TransitionSet`). Метод всегда знает, внутри какого именно перехода произошло событие.

### 📝 Способ 1: Классическая реализация (Анонимный объект)

Через метод `addListener` можно добавить полноценный слушатель (или даже несколько):

Kotlin

```
val t = AutoTransition()
t.addListener(object : Transition.TransitionListener {
   override fun onTransitionStart(transition: Transition?) { /* Код */ }
   override fun onTransitionEnd(transition: Transition?) { /* Код */ }
   override fun onTransitionCancel(transition: Transition?) {}
   override fun onTransitionPause(transition: Transition?) {}
   override fun onTransitionResume(transition: Transition?) {}
})
```

### 🎯 Способ 2: Краткая запись (KTX / Лямбды)

Чтобы не перегружать код пустыми методами, в Android KTX есть удобные inline-расширения, позволяющие слушать только нужные события:

Kotlin

```
val slide = Slide()

// Вариант А: Использование именованных аргументов addListener
slide.addListener(
    onEnd = { /* Тольк по завершению */ },
    onCancel = { /* Только при отмене */ }
)

// Вариант Б: Использование точечных методов-расширений (doOn...)
slide.doOnStart {
    // Выполнится строго на старте анимации
}
```
