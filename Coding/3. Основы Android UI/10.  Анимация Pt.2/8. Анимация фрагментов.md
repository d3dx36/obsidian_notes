Вот структурированное продолжение конспекта для Obsidian, охватывающее анимацию переходов между фрагментами, работу с `ViewPager.PageTransformer` и особенности `Shared Element` транзиций во фрагментах.
## 1. Базовый анимированный переход между фрагментами

Анимация настраивается через свойства самого класса `Fragment` (в блоке `init` или перед транзакцией). Используются те же свойства, что и в Activity: `enterTransition`, `exitTransition`, `returnTransition`, `reenterTransition`.

### Реализация через `init`-блок фрагментов

Kotlin

```
// MainFragment.kt (Исходный фрагмент)
class MainFragment : Fragment() {

   init {
       // Анимация ухода фрагмента (Slide влево)
       exitTransition = Slide(Gravity.START).apply { 
           duration = 800
           mode = Slide.MODE_OUT 
       }
       // Анимация повторного появления при возврате из стек-памяти
       reenterTransition = Slide(Gravity.START).apply { 
           duration = 800 
       }
   }
   
   // ... onCreateView ...

   override fun onStart() {
       super.onStart()
       view?.setOnClickListener {
           val a = activity as FragmentActivity
           a.supportFragmentManager.beginTransaction()
                   .replace(R.id.container, SecondFragment())
                   .addToBackStack("MainFragment")
                   .commit()
       }
   }
}
```

Kotlin

```
// SecondFragment.kt (Целевой фрагмент)
class SecondFragment : Fragment() {

   init {
       // Анимация появления (Slide справа)
       enterTransition = Slide(Gravity.END).apply { duration = 800 }
       // Анимация исчезновения при нажатии "Назад"
       returnTransition = Slide(Gravity.END).apply { 
           duration = 800
           mode = Slide.MODE_OUT 
       }
   }
   
   // ...
}
```

## 2. Анимация страниц с помощью `ViewPager.PageTransformer`

Для кастомизации анимации перелистывания в `ViewPager` используется интерфейс `ViewPager.PageTransformer`. Метод `transformPage(view, position)` принимает текущую страницу и её позицию на экране относительно центра.

### Параметр `position`:

- **`0`** — Страница находится ровно по центру экрана.
    
- **`1`** — Страница полностью уехала вправо.
    
- **`-1`** — Страница полностью уехала влево.
    

### Реализация кастомного трансформера (Эффект масштабирования и прозрачности)

Kotlin

```
const val MIN_SCALE = 0.85f
const val MIN_ALPHA = 0.5f

class ZoomPageTransformer : ViewPager.PageTransformer {

   override fun transformPage(view: View, position: Float) {
       view.apply {
           val pageWidth = width
           val pageHeight = height
           
           when {
               position < -1 -> { // [-Infinity,-1)
                   alpha = 0f // Страница полностью ушла за левый край
               }
               position <= 1 -> { // [-1,1] 
                   // Рассчитываем коэффициент масштабирования
                   val scaleFactor = MIN_SCALE.coerceAtLeast(1 - abs(position))
                   val yMargin = pageHeight * (1 - scaleFactor) / 2
                   val xMargin = pageWidth * (1 - scaleFactor) / 2
                   
                   // Корректируем смещение для сохранения плавности
                   translationX = if (position < 0) {
                       xMargin - yMargin / 2
                   } else {
                       xMargin + yMargin / 2
                   }

                   // Применяем масштабирование
                   scaleX = scaleFactor
                   scaleY = scaleFactor

                   // Изменяем прозрачность в зависимости от масштаба
                   alpha = (MIN_ALPHA + (((scaleFactor - MIN_SCALE) / (1 - MIN_SCALE)) * (1 - MIN_ALPHA)))
               }
               else -> { // (1,+Infinity]
                   alpha = 0f // Страница полностью ушла за правый край
               }
           }
       }
   }
}
```

### Установка трансформера в Activity

Kotlin

```
view_pager.adapter = pagerAdapter
// Задаем способ перемещения страниц
view_pager.setPageTransformer(true, ZoomPageTransformer())
```

## 3. Shared-Element Fragment Transition (Общие элементы)

> [!critique] Главное отличие от Activity В текущей активной иерархии View фрагментов **не может быть двух элементов с одинаковым `transitionName` одновременно**. Из-за этого при работе со списками / сетками `transitionName` приходится переназначать **динамически** прямо в коде.

При переходе между фрагментами общий элемент связывается внутри `FragmentTransaction` с помощью метода `addSharedElement(view, transitionName)`.

### Инструменты управления задержкой анимации

При переходе на новый фрагмент данные (например, тяжелая картинка из сети) могут не успеть загрузиться, из-за чего анимация общего элемента сломается или дернется. Для этого используются два метода:

- `postponeEnterTransition()` — временно приостанавливает выполнение анимации входа.
    
- `startPostponedEnterTransition()` — возобновляет анимацию (вызывается, когда данные отрисованы).
    

### Практическая реализация

#### Код MainFragment (Динамическое управление именами)

Kotlin

```
const val transitionName = "image_name"
const val transitionNameText = "transition_text"

class MainFragment : Fragment() {
   val secondFragment = SecondFragment()

   init {
       // Задаем анимацию для общего элемента целевому фрагменту
       secondFragment.sharedElementEnterTransition = AutoTransition().setDuration(800L)
   }

   override fun onViewCreated(view: View, savedInstanceState: Bundle?) {
       super.onViewCreated(view, savedInstanceState)
       val texts = arrayOf(t1, t2, t3, t4, t5, t6)
       val images = arrayOf(i1, i2, i3, i4, i5, i6)

       // При возврате (обратном переходе) возвращаем transitionName на место
       images[secondFragment.imageIndex].transitionName = transitionName
       texts[secondFragment.imageIndex].transitionName = transitionNameText

       images.forEachIndexed { i, img ->
           img.setOnClickListener {
               // 1. Очищаем transitionName у элементов прошлого перехода
               images[secondFragment.imageIndex].transitionName = ""
               texts[secondFragment.imageIndex].transitionName = ""
               
               // 2. Ставим transitionName ИМЕННО на те View, по которым кликнули сейчас
               img.transitionName = transitionName
               texts[i].transitionName = transitionNameText
               
               // 3. Выполняем транзакцию фрагментов
               parentFragmentManager.beginTransaction()
                   .setReorderingAllowed(true) // Обязательно для Shared-элементов!
                   .addSharedElement(img, transitionName)
                   .addSharedElement(texts[i], transitionNameText)
                   .replace((view.parent as ViewGroup).id, secondFragment.apply {
                       imageIndex = i
                       text = texts[i].text.toString()
                   })
                   .addToBackStack("MainFragment")
                   .commit()
           }
       }
   }
}
```

#### Код SecondFragment (Ожидание загрузки данных)

Kotlin

```
class SecondFragment : Fragment() {
   var imageIndex = 0
   var text: String = ""

   // ... onCreateView ...

   override fun onViewCreated(view: View, savedInstanceState: Bundle?) {
       super.onViewCreated(view, savedInstanceState)
       
       // 1. Приостанавливаем Transition до тех пор, пока View не заполнится контентом
       postponeEnterTransition()
       
       val imageIds = arrayOf(R.drawable.bus, R.drawable.subway, R.drawable.walk, R.drawable.dutch_bike, R.drawable.city_car, R.drawable.airplane)
       
       // Заполняем данными
       image.setImageResource(imageIds[imageIndex])
       text_name.text = text
       
       // 2. Данные установлены и готовы к отрисовке, запускаем анимацию перехода
       startPostponedEnterTransition()
   }
}
```

> [!warning] Важный флаг При транзакции фрагментов с общими элементами всегда вызывайте `.setReorderingAllowed(true)`. Он оптимизирует изменения состояний фрагментов, благодаря чему корректно отрабатывают `postponeEnterTransition()` и анимации перекрытия кадров.
