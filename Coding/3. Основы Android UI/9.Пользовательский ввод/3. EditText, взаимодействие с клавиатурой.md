Когда появляется клавиатура, она занимает значительную часть экрана. Если не настроить поведение UI, поле ввода может оказаться перекрытым.

## 1. Настройка поведения в Manifest (`windowSoftInputMode`)

Поведение задается в файле `AndroidManifest.xml` для конкретной `<activity>`.

### Основные режимы:

- **`adjustNothing`** — Система ничего не делает. Клавиатура просто открывается поверх разметки, часто перекрывая поле ввода.
    
- **`adjustPan`** — Система сдвигает всё содержимое экрана вверх, чтобы активное поле ввода стало видимым.
    
    - _Минус:_ Верхняя часть интерфейса (например, Toolbar) может уйти за пределы экрана.
        
- **`adjustResize`** — Система меняет размер корневого контейнера.
    
    - _Плюс:_ Считается лучшей практикой.
        
    - _Важно:_ Чтобы это работало красиво, используйте `ScrollView` или настраивайте веса в `ConstraintLayout`.
        

### Настройка из кода (Kotlin):

Если нужно изменить режим динамически:

Kotlin

```
window.setSoftInputMode(WindowManager.LayoutParams.SOFT_INPUT_ADJUST_PAN)
```

## 2. Настройка кнопки действия (`imeOptions`)

Вы можете изменить иконку и поведение кнопки "Enter" на клавиатуре с помощью атрибута `android:imeOptions`.

> [!IMPORTANT]
> 
> Чтобы `imeOptions` работали корректно, `android:inputType` **не** должен быть `textMultiLine`. Используйте `text`, `number` и т.д.

### Варианты действий:

|**Значение**|**Иконка / Действие**|**Описание**|
|---|---|---|
|**`actionNext`**|Стрелочка вперед|Переносит фокус на следующее поле ввода.|
|**`actionDone`**|Галочка|Завершает ввод и скрывает клавиатуру.|
|**`actionSearch`**|Лупа|Логика поиска (нужно прописать в коде).|
|**`actionSend`**|Бумажный самолетик|Логика отправки сообщения.|
|**`actionGo`**|Стрелочка|Переход по ссылке или выполнение действия.|

## 3. Обработка нажатия кнопки на клавиатуре

Чтобы "поймать" нажатие кнопки (например, "Готово" или "Поиск"), нужно установить слушатель `setOnEditorActionListener`.

### Пример: Форма с проверкой заполнения

В этом примере мы проверяем, что оба поля заполнены, прежде чем позволить пользователю "завершить" ввод.

Kotlin

```
binding.charInput.setOnEditorActionListener { v, actionId, event ->
    // Проверяем, что нажата кнопка "Готово" (IME_ACTION_DONE)
    if (actionId == EditorInfo.IME_ACTION_DONE) {
        
        val textNum = binding.numberInput.text.toString()
        val textChar = binding.charInput.text.toString()
        
        // Проверка на пустоту (isNotEmpty)
        if (textNum.isNotEmpty() && textChar.isNotEmpty()) {
            Toast.makeText(requireContext(), "Успех! Данные сохранены.", Toast.LENGTH_SHORT).show()
            
            // Снимаем фокус, чтобы клавиатура закрылась
            v.clearFocus() 
        } else {
            Toast.makeText(requireContext(), "Ошибка: заполните все поля!", Toast.LENGTH_SHORT).show()
        }
        
        true // Событие обработано
    } else {
        false // Пропускаем другие действия
    }
}
```

### Полезные методы для проверки текста:

- `isNotEmpty()` — строка не пустая (длина > 0).
    
- `isNotBlank()` — строка не пустая и не состоит только из пробелов (самый надежный вариант для имен/паролей).
    

---

### Совет по UX:

Если у вас много полей ввода, используйте `actionNext` для всех полей, кроме последнего. На последнем ставьте `actionDone`. Это позволит пользователю буквально "пролететь" через форму, не закрывая клавиатуру лишний раз.
