Вот структурированный конспект по работе метода `onMeasure()` в Android на основе предоставленного материала.


`onMeasure()` — ключевой метод жизненного цикла View, в котором определяются размеры элемента на экране (например, для соблюдения пропорций кастомного циферблата).

### 1. Механизм вызова

- Метод `onMeasure()` вызывается **после** метода `measure()`.
    
- Как правило, `measure()` вызывается родительским контейнером (`Layout`) неявно для всех дочерних View, чтобы распределить доступное пространство.
    

### 2. Анатомия MeasureSpec

Сигнатура метода:

Kotlin

```
override fun onMeasure(widthMeasureSpec: Int, heightMeasureSpec: Int)
```

`widthMeasureSpec` и `heightMeasureSpec` — это целые числа (`Int`), в которых с помощью **битового сдвига** закодированы два параметра: **размер** и **режим занимаемой площади** (зависят от настроек в разметке: `wrap_content`, `match_parent`, точный размер в `dp`).

Для извлечения данных используется класс `MeasureSpec`:

Kotlin

```
val widthMode = MeasureSpec.getMode(widthMeasureSpec) // Получение режима (Enum)
val widthSize = MeasureSpec.getSize(widthMeasureSpec) // Получение размера в пикселях
```

### 3. Режимы спецификации (MeasureSpec Modes)

- **`UNSPECIFIED`** — у родителя нет предпочтений по размеру View (размер может быть любым). Часто используется `Layout`-ом при первом проходе дерева элементов для предварительного замера.
    
- **`EXACTLY`** — жесткое ограничение. Родительский контейнер определил точный размер для View (директивно).
    
- **`AT_MOST`** — ограничение «не более чем». Родитель задает максимальный размер, который View может занять (например, при `match_parent` элемент может занять всё выделенное пространство, но не больше).
    

_Пример ручной обработки режимов:_

Kotlin

```
private fun chooseDimension(mode: Int, size: Int) =
   when (mode) {
       MeasureSpec.AT_MOST, MeasureSpec.EXACTLY -> size
       else -> 300 // Дефолтный размер для UNSPECIFIED
   }
```

### 4. Алгоритм расчета размеров

При переопределении метода логика под капотом (и в вашем коде) строится так:

1. Берётся желаемый размер (`MeasureSpec.getSize`).
    
2. Учитываются внутренние отступы — **паддинги** (`paddingTop`, `paddingBottom`, `paddingLeft`, `paddingRight`).
    
3. Итоговые данные анализируются `Layout`-ом. Он может: отобразить как есть, обрезать, добавить скролл, перезапустить `onMeasure()` с другими спецификациями или выбросить `Exception`.
    

#### Функция-помощник `resolveSize()`

Чтобы не сопоставлять режимы вручную, можно использовать встроенный метод:

Kotlin

```
val resolvedWidth = resolveSize(widthSize, widthMeasureSpec)
```

> **Важно:** Вторым параметром в `resolveSize` передается исходный `measureSpec` целиком (из параметров `onMeasure`), а не чистый режим `mode`.

### 5. Финальный этап и пример переопределения

После вычисления финальных значений **обязательно** нужно вызвать метод `setMeasuredDimension(chosenWidth, chosenHeight)`, чтобы сохранить размеры. Без этого приложение упадет с ошибкой.

**Шаблон переопределения `onMeasure`:**

Kotlin

```
override fun onMeasure(widthMeasureSpec: Int, heightMeasureSpec: Int) {
   // 1. Считаем полный размер с учетом паддингов
   val heightSize = MeasureSpec.getSize(heightMeasureSpec) + paddingBottom + paddingTop
   val widthSize = MeasureSpec.getSize(widthMeasureSpec) + paddingLeft + paddingRight
   
   // 2. Получаем конечные размеры View с учетом режима родителя
   val resolvedWidth = resolveSize(widthSize, widthMeasureSpec)
   val resolvedHeight = resolveSize(heightSize, heightMeasureSpec)
   
   // 3. Устанавливаем итоговые размеры (обязательный шаг)
   setMeasuredDimension(resolvedWidth, resolvedHeight)
}
```
