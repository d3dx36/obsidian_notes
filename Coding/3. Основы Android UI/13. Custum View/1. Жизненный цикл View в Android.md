Жизненный цикл View активируется, когда родительский контейнер прикрепляет её к себе (через XML-вёрстку или метод `addView()` в коде).

## Этапы создания View (по порядку вызова)

### 1. Конструктор

Используется для инициализации и передачи данных (контекст, атрибуты стиля).

- **Реализация на Kotlin:** Используется аннотация `@JvmOverloads` для генерации перегруженных конструкторов для Java-кода (с атрибутами и без).
    

Kotlin

```
class CustomView @JvmOverloads constructor(
    context: Context, 
    attributeSet: AttributeSet? = null
) : View(context, attributeSet)
```

### 2. `onAttachedToWindow()` _(Опциональный)_

- Вызывается, когда View прикрепляется к экрану.
    
- В этот момент View получает доступ к информации о других элементах в родительском контейнере.
    

### 3. `onMeasure(widthMeasureSpec, heightMeasureSpec)` _(Важный)_

- Здесь View определяет свой **размер и место** в макете.
    
- Просчитывает параметры `wrap_content`, `match_parent` или фиксированные значения.
    

### 4. `onLayout()` _(Опциональный)_

- Присваивает размеры и позиции для **дочерних View**.
    
- В основном переопределяется при создании кастомных `ViewGroup`.
    

### 5. `onDraw(canvas: Canvas)` _(Критически важный)_

- Отвечает за непосредственную **отрисовку** элемента на экране.
    
- **Canvas** — плоскость (холст), на которой рисуем.
    
- **Paint** — инструмент (кисть), задающий цвет, стиль и толщину.
    

> ⚠️ **Критически важно для производительности:**
> 
> Метод `onDraw()` вызывается очень часто (при скролле, анимациях).
> 
> - **Запрещено** создавать объекты (например, `new Paint()`) внутри `onDraw()`. Это приводит к частой работе Garbage Collector и фризам интерфейса. Инициализацию нужно выносить в конструктор или инициализирующие блоки.
>     
> - **Запрещено** создавать переменные и производить сложные вычисления внутри метода.
>     

## Обновление View

Если состояние View изменилось и его нужно отобразить по-новому, используются два метода:

|**Метод**|**Что делает**|**Когда использовать**|
|---|---|---|
|**`invalidate()`**|Запускает цепочку заново с этапа **`onDraw()`**.|Когда изменился внешний вид (цвет, текст, координаты линии), но **размеры остались прежними**.|
|**`requestLayout()`**|Запускает цепочку с самого начала: **`onMeasure()`** $\rightarrow$ `onLayout()` $\rightarrow$ `onDraw()`.|Когда изменились **размеры** View или окружения (например, соседний элемент исчез и нужно занять его место).|
