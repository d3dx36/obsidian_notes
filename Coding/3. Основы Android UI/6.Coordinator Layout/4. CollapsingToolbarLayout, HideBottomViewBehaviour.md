**CollapsingToolbarLayout** — это обёртка над элементом _Toolbar_. Он создан, чтобы быть дочерним элементом _AppBarLayout_ и участвовать во взаимодействии _View_ при анимации сворачивания/разворачивания.

Давайте разберём, из чего он состоит.

## **Collapsing title**

Здесь, я думаю, всё понятно. Это и есть наш заголовок, который меняет свои размеры в зависимости от свернутости/развернутости `AppBarLayout`:

![img](https://lms-cdn.skillfactory.ru/assets/courseware/v1/0d5fa2be5a81c91d5f0fdc5e71e54bc8/asset-v1:SkillFactory+ANDROID-NEW+2020+type@asset+block/ANDROID_27.4_1.gif)

Текст заголовка задаётся программно, нужно найти наш `CollapsingToolbarLayout` (предварительно задав ему `id`) и задать нужный текст:

```kotlin
binding.toolbarLayout.title = "Skillfactory"
```

> [!danger] Kotlin synthetic больше не работает
> В исходном конспекте здесь предлагалось два варианта: `findViewById` и **Kotlin synthetic** (код вида `toolbar_layout.title = ...` без импорта).
>
> **Kotlin synthetic полностью удалён из Kotlin 1.8** — плагин `kotlin-android-extensions` больше не существует. Такой код просто не скомпилируется: IDE не найдёт символ. Если встретишь его в чужом проекте, знай, что это код из 2017-2020 годов.
>
> Что использовать сейчас — **ViewBinding**. Оно даёт доступ к вьюхам по имени `id` без `findViewById`, с проверкой типов на этапе компиляции:
>
> ```kotlin
> // в build.gradle модуля app
> buildFeatures { viewBinding = true }
> ```
>
> ```kotlin
> private lateinit var binding: ActivityMainBinding
>
> override fun onCreate(savedInstanceState: Bundle?) {
>     super.onCreate(savedInstanceState)
>     binding = ActivityMainBinding.inflate(layoutInflater)
>     setContentView(binding.root)
>
>     binding.toolbarLayout.title = "Skillfactory"   // camelCase из snake_case в id
> }
> ```
>
> Логика простая: `id="@+id/toolbar_layout"` превращается в `binding.toolbarLayout`. Если забудешь задать `id` — получишь ошибку компиляции, а не `NullPointerException` в рантайме.

## **HideBottomViewBehaviour**

При этом поведении ваш _View_ или _ViewGroup_ прячется вниз при скролле вниз и появляется при скролле вверх, в **Scroll-Based** он ведёт себя таким образом:

![img](https://lms-cdn.skillfactory.ru/assets/courseware/v1/def24640e9de735159df21f78c446755/asset-v1:SkillFactory+ANDROID-NEW+2020+type@asset+block/ANDROID_27.4_3.gif)

То есть он начнёт убираться после того, как схлопнется `**AppBarLayout**` при скролле вниз, и будет сразу появляться при скролле наверх.

Соответственно, в **Layout-Based** поведение будет такое:

![img](https://lms-cdn.skillfactory.ru/assets/courseware/v1/90661b78a50916346ee48e7315f5f4e3/asset-v1:SkillFactory+ANDROID-NEW+2020+type@asset+block/ANDROID_27.4_4.gif)

То есть наш `**BottomView**` будет убираться сразу при скролле вниз и сразу появляться при скролле вверх.

И в том, и в другом случае код для нашего `**BottomView**` будет такой:

<FrameLayout
   android:id="@+id/bottom_view"
   android:layout_width="match_parent"
   android:layout_height="70dp"
   android:layout_gravity="bottom"
   app:layout_behavior="com.google.android.material.behavior.HideBottomViewOnScrollBehavior"
   android:background="@drawable/rect_grad">
	<TextView
       android:layout_width="wrap_content"
       android:layout_height="wrap_content"
       android:text="BottomViewLayout"
       android:textSize="24sp"
       android:layout_gravity="center"
       android:textColor="@android:color/white"/>
</FrameLayout>

По большому счёту, главное для нас — атрибут `app:layout_behavior="com.google.android.material.behavior.HideBottomViewOnScrollBehavior"`, а контейнер или _View_ мы можем использовать любой, ну и также не забываем указывать `android:layout_gravity="bottom"`, иначе должного эффекта будет не достичь.
