К этому моменту у вас уже накопился приличный арсенал знаний для работы с анимациями. И я не вижу причин останавливаться на достигнутом. Давайте посмотрим на ещё один подход к применению анимаций.

**View Property Animation** будет удобен при реализации анимации в классе на основе логики. С изменением представления будут меняться и свойства _View,_ то есть мы анимируем _View_ по какому-то событию. Например, плавное нажатие кнопки сделает _View_ на рисунке ниже невидимым:

![рисунок](https://lms-cdn.skillfactory.ru/assets/courseware/v1/3a8c0a5b2fb52d374f4fc409e3860240/asset-v1:SkillFactory+ANDROID-NEW+2020+type@asset+block/ANDROID_25.6_1.gif)

Ничего необычного: берём `ValueAnimator` или `ObjectAnimator` и делаем такую красоту. Но **View Property Animation** позволяет нам делать это, используя удобный и читабельный синтаксис. Давайте посмотрим, как выглядит, код из примера выше:

button.setOnClickListener {
   android_icon.animate()
       .setDuration(300)
       .setInterpolator(DecelerateInterpolator())
       .alpha(0f)
       .start()
}

По мне так очень удобно, особенно, когда у нас эта анимация создаётся и используется только для одного объекта. Давайте разберём, как это применять.

Для начала мы на нашем _View_ вызываем метод `animate()`, и дальше, как в паттерне `Builder`, применяем установки для нашей анимации:

- Устанавливаем время, за которое анимация должна проиграться: `.setDuration(300)` .
- Применяем интерполятор по вкусу (в предыдущем юните мы узнали, как их много).
- Устанавливаем, что будем анимировать и **до** какого значения: `alpha(0f)`.
    
    То есть мы не можем задать **от** какого значения, начальное значение берётся из текущего состояния _View_. Если нужно задать какое-то особое состояние, то нужно задать его перед вызовом анимации. К примеру, если мы хотим проявлять View, то перед анимацией надо задать `alpha = 0`, а в `animator` устанавливаем `.alpha(1f)`.
    
- Также можно установить слушатель, чтобы возвращать коллбэки:
    
    .setListener(object: Animator.AnimatorListener {
       override fun onAnimationRepeat(p0: Animator?) {
           TODO("Not yet implemented")
       }
    
       override fun onAnimationEnd(p0: Animator?) {
           TODO("Not yet implemented")
       }
    
       override fun onAnimationCancel(p0: Animator?) {
           TODO("Not yet implemented")
       }
    
       override fun onAnimationStart(p0: Animator?) {
           TODO("Not yet implemented")
       }
    
    })
    
    Вы уже знаете, что делать в коллбэках, поэтому пойдем дальше.
    
- Можно установить запуск анимации с отсрочкой, иногда это нужно: `.setStartDelay(300)`.
- Через лямбду вы можете выполнять какой-либо код на старте анимации, это код будет выполняться в отдельном потоке: `.withStartAction **{}**`.
- То же самое, только в конце анимации: `.withEndAction **{}**`.
- `.start()` — вообще, если вы не укажете этот метод, анимация всё равно начнётся после применения всех настроек, поэтому явно вызывать его не надо.
