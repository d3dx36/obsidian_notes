### **1. Что такое Activity?**

**Activity** (Активити) — это основной компонент Android-приложения, который представляет собой один экран с пользовательским интерфейсом.

- Почти все активити взаимодействуют с пользователем, поэтому класс активити создает окно, в котором вы можете разместить свой интерфейс.
    
- Приложение обычно состоит из нескольких активити, которые слабо связаны между собой.
    

### **2. Жизненный цикл (Activity Lifecycle)**

Система управляет состоянием активити через специальные методы-коллбэки. Это позволяет приложению не терять данные при входящем звонке или перевороте экрана.

| Метод             | Что происходит                                                                                         |
| ----------------- | ------------------------------------------------------------------------------------------------------ |
| **`onCreate()`**  | Вызывается при создании. Здесь инициализируем View (binding) и устанавливаем макет (`setContentView`). |
| **`onStart()`**   | Активити становится видимой пользователю.                                                              |
| **`onResume()`**  | Активити выходит на передний план. Пользователь может с ней взаимодействовать.                         |
| **`onPause()`**   | Активити частично перекрыта (например, диалоговым окном). Взаимодействие приостановлено.               |
| **`onStop()`**    | Активити больше не видна (пользователь открыл другой экран).                                           |
| **`onDestroy()`** | Активити полностью уничтожается (при вызове `finish()` или системой).                                  |
### **3. Связь с Manifest**

Активити не будет работать, если её не зарегистрировать в файле **AndroidManifest.xml**.

- Если активити должна быть главной (запускаться при клике на иконку), внутри неё прописывается `intent-filter` с категорией `LAUNCHER`.
    

XML

```
<activity android:name=".MainActivity">
    <intent-filter>
        <action android:name="android.intent.action.MAIN" />
        <category android:name="android.intent.category.LAUNCHER" />
    </intent-filter>
</activity>
```

### **4. Навигация и Intent**

Для перехода между экранами используется объект **Intent** (Намерение).

- **Явный Intent (Explicit):** Используется для запуска конкретной активити в твоем приложении.
    
    Kotlin
    
    ```
    val intent = Intent(this, SecondActivity::class.java)
    startActivity(intent)
    ```
    
- **Передача данных:** Данные можно передать через метод `putExtra()`.
    
    Kotlin
    
    ```
    intent.putExtra("key", "Hello, Second Screen!")
    ```
    

---

### **5. Использование View Binding**

Современный стандарт для доступа к элементам XML-верстки без использования тяжелого `findViewById`.

- В методе `onCreate` мы "раздуваем" (inflate) макет и передаем его корень в `setContentView`.
    

Kotlin

```
private lateinit var binding: ActivityMainBinding

override fun onCreate(savedInstanceState: Bundle?) {
    super.onCreate(savedInstanceState)
    binding = ActivityMainBinding.inflate(layoutInflater)
    setContentView(binding.root)
    
    binding.myButton.setOnClickListener { /* действие */ }
}
```

---

### **6. Важные особенности**

- **Смена конфигурации:** При повороте экрана активити по умолчанию полностью уничтожается и создается заново.
    
- **Наследование:** Чаще всего мы наследуемся от **`AppCompatActivity`**, чтобы приложение выглядело одинаково и на старых, и на новых версиях Android.
    
- **Завершение работы:** Чтобы программно закрыть текущий экран, используется метод `finish()`.

## Метод Log.d()
Метод **`Log.d()`** — это твой главный инструмент для "прослушки" приложения. Буква **`d`** означает **Debug** (отладка). Он выводит сообщения в специальное окно **Logcat**, помогая понять, что происходит внутри кода, когда приложение запущено.

### 1. Синтаксис метода

Метод принимает два обязательных строковых параметра:

Log.d(TAG,message)

- **`TAG`**: "Метка", по которой ты будешь фильтровать свои сообщения среди тысяч системных логов. Обычно это имя класса.
    
- **`message`**: Сам текст сообщения (что именно ты хочешь сообщить).
    

---

### 2. Пример использования в коде

Допустим, ты хочешь проверить, вызывается ли метод жизненного цикла, или узнать значение переменной:

Kotlin

```
class MainActivity : AppCompatActivity() {

    // Создаем константу для тега (удобно, чтобы не опечататься)
    private val TAG = "Lifecycle_Log"

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContentView(R.layout.activity_main)

        Log.d(TAG, "onCreate вызван!") // Просто текст

        val counter = 5
        Log.d(TAG, "Значение счетчика: $counter") // Текст с переменной
    }
}
```

---

### 3. Где смотреть результат?

Все логи попадают в окно **Logcat**. Оно находится в нижней части Android Studio.

**Чтобы найти свои логи:**

1. Открой вкладку **Logcat** (внизу).
    
2. В поле поиска введи свой тег (например, `Lifecycle_Log`).
    
3. Убедись, что выбран уровень логирования **Debug** (или выше).
    

---

### 4. Другие уровни логирования

Помимо `Log.d`, есть и другие уровни. Они подкрашиваются разными цветами:

- `Log.v()` (**Verbose**) — самая подробная информация (белый).
    
- `Log.d()` (**Debug**) — для отладки в процессе разработки (синий/зеленый).
    
- `Log.i()` (**Info**) — общая информация о работе (зеленый).
    
- `Log.w()` (**Warn**) — предупреждения, что что-то идет не так (желтый).
    
- `Log.e()` (**Error**) — ошибки, из-за которых что-то упало или не сработало (красный).
    

---

### 5. Лайфхак: Быстрый ввод

В Android Studio есть горячие клавиши для логов:

1. Напечатай **`logd`** и нажми `Tab`. IDE сама развернет это в `Log.d(TAG, "")`.
    
2. Чтобы создать тег в начале класса, напечатай **`logt`** и нажми `Tab` — появится `private val TAG = "ClassName"`.


## **Золотые правила разработчика:**

1. **Не делай `onCreate` тяжелым**: Длительные операции (загрузка из сети) в этом методе приведут к тому, что приложение будет "тормозить" при запуске.
    
2. **Следи за ресурсами**: Если ты запустил анимацию в `onResume`, обязательно останови её в `onPause`.
    
3. **Используй логирование**: Чтобы понять, как работает жизненный цикл, добавь `Log.d("Lifecycle", "OnCreate called")` в методы и посмотри на вывод в Logcat.
