
По сути **фрагменты** представляют собой часть пользовательского интерфейса, имеют свой собственный жизненный цикл (хоть он и связан с активити, про бразильский сериал помните) и также имеют свой обработчик событий.

Фрагменты могут присоединяться и отсоединяться в рамках одного активити. Их можно добавлять как в XML, так и в коде, а также у фрагментов есть свой собственный класс, унаследованный от `Fragment`, и своя вёрстка в XML.

Фрагменты были представлены в _API 11_, в основном они были призваны решить проблему размещения контента на больших экранах, в то время стали появляться планшеты. Так как у планшета гораздо больший экран, чем у телефона, стало быть, и контента влезть должно больше. До фрагментов это можно было решить с помощью другой вёрстки, то есть надо было каждый элемент _UI_ представлять в соответствии с большим экраном. А если мы ещё хотели, чтобы открылись, к примеру, список и содержимое списка, то надо было запускать два активити и настраивать сложное взаимодействие между ними.

При помощи фрагмента мы в рамках одной активити можем открывать сколько угодно фрагментов и легко обмениваться между ними информацией. Возьмем, к примеру, новостное приложение. На телефоне у нас список новостей и сама новость — это разные экраны, но на планшете мы можем себе позволить сразу оба этих экрана.

На первый взгляд немного пугает, но это только на первый взгляд. Давайте разбираться сначала с жизненным циклом фрагмента. По большому счёту он такой же, как и активити, но у него больше подготовительных методов в начале и в конце жизненного цикла. Связано это с тем, что каждый фрагмент прикрепляется к активити. Если в активити логику инициализации мы размещали в методе `**onCreate()**`, то во фрагментах вы её можете размещать как в том же методе `**onCreate()**`, так и в `**onCreateView()**`.

Связь активити и фрагмента тоже довольно прямолинейна: вызванный метод `**onCreate()**` у активити вызывает цепочку методов от `**onAttach()**` до `**onActivityCreated()**`. `**onStart()**` вызывает `**onStart()**`, `**onResume()**` вызывает `**onResume()**` и т.д. Только `**onDestroy()**` вызовет цепочку от `**onDestroyView()**` до `**onDetach()**`.

Итак, создадим наш фрагмент. Есть два способа его создания: вручную, или используя средства _Android Studio_.

Вручную нам надо будет создать класс, наследовать его от `Fragment`, переопределить в нём методы для наших нужд, но обязательно нам нужно будет переопределить либо `**onCreate()**`, либо `**onViewCreated()**`, в них можно что-то инициализировать. А в методе `**onCreateView()**` мы привязываем файл XML для инициализации нашей вёрстки. Потом создать файл **XML**, привязать его к нашему классу. В общем, я описывать это устал, не то что создавать. Давайте сделаем это удобно, при помощи встроенных средств :)

Для того чтобы создать фрагмент, кликните по любой папке правой кнопкой мыши и выберите `**New** → **Fragment** → **Fragment(Blank)**`, как видите, нам предлагается много вариантов для создания фрагмента, но мы выберем самый простой:

![img](https://lms-cdn.skillfactory.ru/assets/courseware/v1/b0f7f3770627f4ed668aa8ef23bbac91/asset-v1:SkillFactory+ANDROID-NEW+2020+type@asset+block/ANDROID_28.4_4.png)

В открывшемся диалоговом окне просто указываем, как будет называться наш фрагмент.

Здесь хочу отметить принятые **правила нейминга**: название класса фрагмента должно заканчиваться на `**Fragment**`, то есть класс `Login` для фрагмента будет `LoginFragment`. Поле `**Fragment Name**` как раз задаёт имя класса, а в `**Fragment Layout Name**` указывается имя XML-класса, связанного с фрагментом, его имя должно начинаться с `**fragment_**`, то есть для класса `LoginFragment` _layout_ файл будет называться [**fragment_login.xml***](https://lms.skillfactory.ru/xblock/block-v1:SkillFactory+ANDROID-NEW+2020+type@vertical+block@8f26259b6d6a484980448aa131de8635?show_title=0&show_bookmark_button=0&recheck_access=1&view=student_view&format=Homework#info).

Не волнуйтесь, сейчас большая часть написанного кода нам не понадобится, да давайте даже лишнее удалим и оставим только то, что нам нужно. Вот так выглядит «обезжиренный» вариант нашего фрагмента:

`import android.os.Bundle`
`import androidx.fragment.app.Fragment`
`import android.view.LayoutInflater`
`import android.view.View`
`import android.view.ViewGroup`

`class MyFragment : Fragment() {`

   `override fun onCreateView(`
       `inflater: LayoutInflater, container: ViewGroup?,`
       `savedInstanceState: Bundle?`
   `): View? {`
       `return inflater.inflate(R.layout.fragment_my, container, false)`
   `}`

   `override fun onViewCreated(view: View, savedInstanceState: Bundle?) {`
       `super.onViewCreated(view, savedInstanceState)`
   `}`
`}`

Вот так, ничего лишнего. Перейдем в файл XML и добавим туда что-нибудь для отображения, например, `ScrollView` c длинным текстом, чтобы можно было его поскроллить:

<FrameLayout xmlns:android="http://schemas.android.com/apk/res/android"
   xmlns:tools="http://schemas.android.com/tools"
   android:layout_width="match_parent"
   android:layout_height="match_parent"
   android:background="@android:color/holo_orange_dark"
   tools:context=".MyFragment">
  
   <ScrollView
       android:layout_width="match_parent"
       android:layout_height="match_parent">
      
       <TextView
           android:layout_width="match_parent"
           android:layout_height="wrap_content"
           android:textSize="25sp"
           android:textColor="@android:color/white"
           android:text="@string/long_text"/>
   </ScrollView>

</FrameLayout>

Теперь осталось только добавить наш фрагмент в активити. Делается это с помощью тэга `<fragment>`, вы можете задать размеры и расположение, и обязательно **`id`** фрагмента, иначе не запустится:

<?xml version="1.0" encoding="utf-8"?>
<androidx.constraintlayout.widget.ConstraintLayout xmlns:android="http://schemas.android.com/apk/res/android"
   xmlns:app="http://schemas.android.com/apk/res-auto"
   xmlns:tools="http://schemas.android.com/tools"
   android:layout_width="match_parent"
   android:layout_height="match_parent">

   <fragment
       android:id="@+id/fragment1"
       android:layout_width="match_parent"
       android:layout_height="300dp"
       android:name="com.amsdevelops.myapplication.MyFragment"
       app:layout_constraintTop_toTopOf="parent"/>

</androidx.constraintlayout.widget.ConstraintLayout>

## Как создать переключение фрагментов по кнопке

### Код

```
package com.example.emptyproject  
  
import android.os.Bundle  
  
import androidx.appcompat.app.AppCompatActivity  
import androidx.fragment.app.Fragment  
import com.example.emptyproject.databinding.ActivityMainBinding  
  
class MainActivity : AppCompatActivity() {  
    private lateinit var binding: ActivityMainBinding  
    override fun onCreate(savedInstanceState: Bundle?) {  
        super.onCreate(savedInstanceState)  
        binding = ActivityMainBinding.inflate(layoutInflater)  
        setContentView(binding.root)  
        if (savedInstanceState == null) {  
            replaceFragment(FirstFragment(), addToBackStack = false)  
        }        binding.button.setOnClickListener {  
            replaceFragment(FirstFragment())  
        }  
        binding.button2.setOnClickListener {  
            replaceFragment(SecondFragment())  
        }  
    }  
  
    // Немного прокачаем функцию: добавим возможность НЕ сохранять в историю (для первого экрана)  
    private fun replaceFragment(fragment: Fragment, addToBackStack: Boolean = true) {  
        val transaction = supportFragmentManager.beginTransaction()  
            .replace(R.id.main_container, fragment)  
        if (addToBackStack) {  
            transaction.addToBackStack(null)  
        }        transaction.commit()  
    }}
```
