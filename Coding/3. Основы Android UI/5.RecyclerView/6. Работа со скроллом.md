## **методы** **для вызова скролла**.

|   |   |
|---|---|
|**Метод**|**Описание**|
|fun setOnScrollListener(listener: RecyclerView.OnScrollListener?)|Устанавливает слушатель на прокручивание списка|
|fun scrollToPosition(position: Int)|Прокручивает список к позиции|
|fun smoothScrollToPosition(position: Int)|Плавно прокручивает список к позиции|
|fun smoothScrollBy(@Px dx: Int, @Px dy: Int)|Плавно прокручивает список на значение `dx, dy` в пикселях|
|fun stopScroll()|Останавливает текущий скролл|

Рассмотрим примеры.

**1**

При работе со **скроллом** очень часто бывает нужно узнать, на какой позиции сейчас находится список.

`MainActivity.kt`

val layoutManager = recyclerView.layoutManager as LinearLayoutManager
var savePositionFirst = layoutManager.findFirstCompletelyVisibleItemPosition()
var savePositionLast = layoutManager.findLastCompletelyVisibleItemPosition()

**2**

Для начала, допустим, нам необходимо реализовать функционал, который есть в приложении _VK_ и подобных: скроллим список наверх, запоминая текущую позицию, а потом скроллим обратно к сохраненной позиции. Для реализации этого функционала достаточно воспользоваться методом `**scrollToPosition**`.

`MainActivity.kt`

savePosition = (recyclerView.layoutManager as LinearLayoutManager).findLastCompletelyVisibleItemPosition()

fun scrollToStart() {
    recyclerView.smoothScrollToPosition(0)
}
fun scrollToSavePosition() {
    recyclerView.scrollToPosition(savePosition)
}

scrollToStart()
scrollToSavePosition()

В данном примере для получения текущей позиции используется метод `findLastCompletelyVisibleItemPosition`, который возвращает позицию последнего видимого элемента. Осталось только реализовать функции скролл к началу и к сохранённой позиции.

**3**

Также, к примеру, можно реализовать подгрузку данных по мере пролистывания. Для этого нам понадобится функция `**setOnScrollListener**`.

Автоматическая загрузка данных вызывается, если пользователь прокрутил список до конца. Чтобы узнать, когда происходит пролистывание списка, необходимо задать обработчик события `onScroll`. За обработчик этого события отвечает `RecyclerView.OnScrollListener`.

`MainActivity.kt`

var isLoading = false
val scrollListener = object: RecyclerView.OnScrollListener() {
    @Override
    override fun onScrolled(recyclerView: RecyclerView, dx: Int, dy: Int) {
        val layoutManager = recyclerView.layoutManager as RecyclerView.LayoutManager
        //смотрим сколько элементов на экране
        val visibleItemCount: Int = layoutManager.childCount
        //сколько всего элементов
        val totalItemCount: Int = layoutManager.itemCount

        //какая позиция первого элемента
        val firstVisibleItems = (recyclerView.layoutManager as LinearLayoutManager).findFirstVisibleItemPosition()

        //проверяем, грузим мы что-то или нет
        if (!isLoading) {
            if (visibleItemCount + firstVisibleItems >= totalItemCount) {
                //ставим флаг, что мы попросили еще элементы
                isLoading = true
                //Вызывает загрузку данных в RecyclerView
            }
        }
    }
}
recyclerView.setOnScrollListener(scrollListener)

**Не забываем назначить его:**

recyclerView.setOnScrollListener(scrollListener)

Загружаем следующую партию данных и добавляем их в адаптер, после добавления вызываем у адаптера `**notifyDataSetChanged**` или используем `**DiffUtil**`, и ставим флаг `isLoading = false`.

В адаптере вам нужно сделать, чтобы его размер был `(реальный размер + 1)`, и отображать последний элемент как индикатор загрузки.

**4**

Допустим, пользователь добавляет в конец списка какой-либо элемент. Чтобы его можно было сразу видеть, необходимо проскроллить список в конец:

`MainActivity.kt`

recyclerView.smoothScrollToPosition(adapter.itemCount -1)

В примере выше, чтобы узнать количество элементов в списке, происходит обращение к адаптеру и его свойству `**itemCount**`. Гетер этого свойства мы как раз переопределяем при реализации класса адаптера.

## **StateRestorationPolicy**

При смене ориентации приложения происходит его пересоздание, то есть метод `onCreate` вызывается еще раз. Это означает, что позиция скролла сбросится, и пользователю придётся опять искать нужную информацию. Только представьте, что вы нашли нужный сериал на _Netflix_, переворачиваете смартфон, а вы опять в начале списка… Обидно вышло. Для того чтобы сохранить позицию скролла, существует `**StateRestorationPolicy**`. Рассмотрим, как его можно реализовать.

`MainActivity.kt`

class MainActivity: AppCompatActivity() {
    private lateinit
    var layoutManager: RecyclerView.LayoutManager
    private val KEY_MANAGER_STATE: String = "KeyForLayoutManagerState"

    override fun onCreate(savedInstanceState: Bundle ? ) {
        super.onCreate(savedInstanceState)
        setContentView(R.layout.activity_main)
        val recyclerView: RecyclerView = findViewById(R.id.recycler_view)
        layoutManager = recyclerView.layoutManager!!
            fun restoreState() {
                val outState: Parcelable ? = savedInstanceState ? .getParcelable(KEY_MANAGER_STATE)
                layoutManager.onRestoreInstanceState(outState)
            }
        restoreState()
    }


    override fun onSaveInstanceState(savedInstanceState: Bundle) {
        super.onSaveInstanceState(savedInstanceState)
        savedInstanceState.putParcelable(KEY_MANAGER_STATE, layoutManager.onSaveInstanceState());
    }
}

Метод `onRestoreInstanceState` восстанавливает сохраненное состояние для `**layoutManager**`. Чтобы сохранить состояние `**layoutManager**`, необходимо переопределить метод жизненного цикла активити `**onSaveInstanceState**`, который и позволяет записать в `**Bundle**` текущее состояние списка `RecyclerView`.
