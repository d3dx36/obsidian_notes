**RecyclerView** должен отображать данные **списком**. Какой именно список и какие типы данных там хранятся — нам неизвестно.  Когда мы хотим предусмотреть в своём классе возможность встроить какую-либо функциональность при использовании нашего класса, мы создаём _события_. Пользователь нашего класса может просто задать обработчик на это событие. Это пример простого **паттерна программирования**. 
## **Паттерн программирования Adapter**

Любой список состоит из данных. _RecyclerView_ просто их отображает. Разработчики класса _RecyclerView_ не могут предположить, какие данные вы захотите показать в своём списке. 

Для отображения данных _RecyclerView_ использует объекты **`RecyclerView.Adapter`**. Именно этот класс «адаптирует» пользовательские данные для отображения в списке.

В **адаптере** мы определяем модель данных, способ их отрисовки и способ передачи данных из списка в представление.

Давайте посмотрим на схеме, как работает адаптер:

Разберём схему более подробно:

1. В _RecyclerView_ есть `LayoutManager`, который располагает элементы на экране.
2. Сам список элементов предоставляется адаптером.
3. В `Adapter` определяется связь с `DataSet` (данные, которые необходимо отобразить).
4. Адаптер имеет связь с `ViewHolder`.
5. _RecyclerView_ создаёт новые ViewHolder через реализацию `onCreateViewHolder Adapter`.
6. Adapter даёт возможность для _RecyclerView_ **переиспользовать** объекты ViewHolder.
7. Адаптер передаёт данные из DataSet в ViewHolder.
8. ViewHolder предоставляет **визуальную часть** элемента списка — то, как он будет отрисовываться.

Самое интересное здесь заключается именно в _переиспользовании_ уже созданных ViewHolder-ов. Когда пользователь листает список, _RecyclerView_ решает, что для отображения новых _View_ можно использовать уже созданные ранее, так как их пользователь  уже не видит. Вместо создания новых _View_, используются старые, просто в них передаются новые данные из списка данных в адаптере. За счет этого происходит экономия памяти.

## **Holder**

Также вы могли заметить новое понятие — `**ViewHolder**`. Этот класс является обёрткой над View, а View является элементом списка. Для всех элементов списка создаётся один XML-файл разметки. Именно `ViewHolder` позволяет обратиться к экземпляру View каждого элемента списка. Например, в классе `ViewHolder` можно  привязать к отдельным переменным те или иные View_,_ из которых состоит разметка этого элемента. Также можно написать функции для анимирования этого элемента списка или обработать события пользовательского ввода.
