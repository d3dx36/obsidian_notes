**RecyclerView** — это гибкий инструмент для отображения списков. Он экономит ресурсы, переиспользуя созданные View (ячейки), которые ушли за экран.

### 1. Модель данных

Создаем простой `data class`, который описывает объект (например, фильм).

Kotlin

```
data class Film(
    val poster: Int,      // ID ресурса (R.drawable. ...)
    val name: String, 
    val description: String
)
```

### 2. Разметка элементов (item.xml)

Крайне важно, чтобы высота контейнера была `wrap_content`, иначе один элемент займет весь экран.

XML

```
<androidx.constraintlayout.widget.ConstraintLayout 
    android:layout_width="match_parent"
    android:layout_height="wrap_content"> 
    <ImageView android:id="@+id/poster" ... />
    <TextView android:id="@+id/name" ... />
    <TextView android:id="@+id/description" ... />

</androidx.constraintlayout.widget.ConstraintLayout>
```

### 3. ViewHolder

Класс, который хранит ссылки на все View внутри одного элемента списка. Это позволяет не вызывать `findViewById` каждый раз при прокрутке.

Kotlin

```
class PhotoViewHolder(val binding: ItemBinding) : RecyclerView.ViewHolder(binding.root) {
    fun bind(photo: Photo) {
        binding.tittle.text = photo.tittle 
        binding.poster.setImageResource(photo.poster)
    }
}
```

### 4. Адаптер (PhotoAdapter)

Связующее звено между данными и списком.

- `onCreateViewHolder` — создает новый ViewHolder и надувает (inflate) XML.
    
- `onBindViewHolder` — наполняет ViewHolder данными конкретного элемента.
    
- `getItemCount` — возвращает размер списка.
    

Kotlin

```
class PhotoAdapter(val contentList: List<Photo>) : RecyclerView.Adapter<PhotoViewHolder>() {  
    override fun onCreateViewHolder(  
        parent: ViewGroup,  
        viewType: Int,  
    ): PhotoViewHolder {  
       val binding= ItemBinding.inflate(LayoutInflater.from(parent.context),parent,false)  
       return PhotoViewHolder(binding)  
    }  
    override fun onBindViewHolder(  
        holder: PhotoViewHolder,  
        position: Int,  
    ) {  
       holder.bind(contentList[position])  
    }  
    override fun getItemCount(): Int {  
        return contentList.size  
    }  
}
```

Вот подробный разбор каждой части:

#### 1. `class PhotoAdapter`

Вы объявляете новый класс. Адаптер — это посредник. Он берет данные из вашего списка и решает, в какую «ячейку» (ViewHolder) их положить.

#### 2. `(val contentList: List<Photo>)`

Это **конструктор** класса.

- **`contentList`**: Это то, что адаптер будет отображать. В данном случае это список объектов типа `Photo`.
    
- Вы передаете этот список один раз при создании адаптера в `MainActivity` (например, `PhotoAdapter(myPhotos)`).
    

#### 3. `: RecyclerView.Adapter`

Ваш класс **наследуется** от базового класса `RecyclerView.Adapter`. Это говорит системе Android: «Этот класс умеет работать со списками и понимает правила RecyclerView».

#### 4. `<PhotoViewHolder>`

Это **Generic (обобщение)**. Вы указываете адаптеру, какой именно тип `ViewHolder` он должен использовать для отрисовки элементов.

- **Зачем это нужно:** Чтобы внутри адаптера (в методе `onBindViewHolder`) вы могли сразу обращаться к полям вашего `PhotoViewHolder` (например, к `binding.tittle`), не занимаясь приведением типов.
    

---

#### Как это работает вместе (Аналогия)

Представьте, что **RecyclerView** — это пустая полка в магазине, а ваш **PhotoAdapter** — это работник склада:

1. **`contentList`**: Это коробка с товарами (вашими фото), которую принесли работнику.
    
2. **`PhotoViewHolder`**: Это пустые стандартные контейнеры, в которые работник раскладывает товар.
    
3. **`Adapter`**: Это сам процесс работы. Работник берет товар из коробки (`onBindViewHolder`), кладет его в контейнер и ставит на полку.
### 5. Инициализация в MainActivity

Чтобы список заработал, нужно задать ему `LayoutManager` (способ расположения элементов) и `Adapter`.

Kotlin

```
class MainActivity : AppCompatActivity() {  
    lateinit var binding: ActivityMainBinding  
    val contentList: ArrayList<Photo> = arrayListOf(  
        Photo("set1",R.drawable.ic_huangjin_er_bi_wang_photo_retouching_practice_01),  
        Photo("set2",R.drawable.ic_huangjin_er_bi_wang_photo_retouching_practice_02),  
        Photo("set3",R.drawable.ic_huangjin_er_bi_wang_photo_retouching_practice_03),  
        Photo("set4",R.drawable.ic_huangjin_er_bi_wang_photo_retouching_practice_04),  
        Photo("set5",R.drawable.ic_huangjin_er_bi_wang_photo_retouching_practice_05),  
    )  
  
    override fun onCreate(savedInstanceState: Bundle?) {  
        super.onCreate(savedInstanceState)  
        binding = ActivityMainBinding.inflate(layoutInflater) // 1. Инициализация  
        setContentView(binding.root)  
  
        binding.item.layoutManager= LinearLayoutManager(this)  
        binding.item.adapter= PhotoAdapter(contentList)  
    }  
}
```

### Коротко о главном:

|**Компонент**|**Роль**|
|---|---|
|**Model**|Что показываем (данные)|
|**Item Layout**|Как выглядит одна ячейка (дизайн)|
|**ViewHolder**|Кто держит ссылки на вьюшки (память)|
|**Adapter**|Кто связывает данные и дизайн (логика)|
|**LayoutManager**|Как располагать (список/сетка)|
    

**Совет:** Для улучшения производительности и плавных анимаций при обновлении списка всегда старайся использовать **DiffUtil** вместо `notifyDataSetChanged()`.
